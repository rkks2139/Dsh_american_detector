# 评分模型（v2：贝叶斯对数几率）

## 为什么不是加权求和

v1 给每个信号一个 0~22 的权重，命中就相加，`>= 60` 判为美国用户。这有两个数学问题：

1. **概率不能相加。** 权重不是概率，累加出来的数字没有可解释的尺度。
2. **无法表达负证据。** v1 的权重非零即正，所以"看见拼音输入法"和"没看见美国软件"这两件**降低**了
   美国用户概率的事，只能记 0 分——它们本该是反向证据。

v2 每个信号给出**对数几率**（log-odds，朴素贝叶斯加数）：

```
L = ln( P(该观测 | 美国用户) / P(该观测 | 非美国用户) )
```

| L | 含义 |
|---|---|
| `> 0` | 该观测更可能出现在美国用户身上 |
| `< 0` | 该观测更可能出现在非美国用户身上（**反向证据**） |
| `0` | 该观测没有信息量（含 `informational` 行） |

判定为美国用户的条件是 `Σ L >= THRESHOLD_LOGIT`（当前 **2.2**）。

> 真值不是概率：信号之间相关，先验也不是 50/50。所以阈值**不是推导出来的，而是用画像标定的**
> ——见 `scripts/calibrate.mjs`。

## 共因折叠（为什么必须做）

`∑ L` 只在**条件独立**时才是贝叶斯正确的。v1 把"浏览器语言是英文""页面语言是英文""用 12 小时制"
当成三个独立证据加了 34 分，而它们其实是**同一个事实**（浏览器是英文的）被数了三遍。
v2 给每个信号一个 `group`，同一组内只保留绝对值最大的那一条，其余标记 `demoted`（弹窗里显示为 **▪ 折叠**）：

| group | 包含的信号 | 为什么归为一组 |
|---|---|---|
| `ui-language` | 浏览器语言、页面语言、12 小时制 | 都是"浏览器 UI 是英文的" |
| `geo-identity` | 浏览器时区、主机时区、系统区域、输入法、跨源一致性 | 都是"这个人来自哪里" |
| `browser-vendor` | 浏览器出品方 | 单独一个事实 |
| `browser-host` | 浏览器与主机是否自洽 | 覆盖/伪造的旁证 |
| `software` / `llm` / `proxy` / `os` / `container` / `ip` | 各自一族 | 互相独立 |
| `meta` | 主机环境、UA 平台 | 仅记录，不计分 |

### 跨源一致性（`src/client/browser-signals.js` 计算）

只有客户端能算这一项：它同时看得到浏览器时区/语言**和**主机报告里的时区/区域/输入法/IP。

| 情形 | L | 说明 |
|---|---|---|
| ≥3 个来源全部指向美国（标 `hard`） | +2.0 | 最强判定依据 |
| 浏览器语言与浏览器时区都指向美国、无主机来源可比 | +0.8 | 只有两个浏览器级事实，权重中等 |
| **伪造特征**：时区指向美国但区域/输入法指向中文圈（或反向） | +1.8 | 时钟或区域被覆盖的典型形状 |
| 部分指向美国、部分指向中国（非上述形状） | +1.0 | 混合 |
| ≥2 个来源一致指向中国、无来源指向美国 | −1.5 | 对"美国用户"的强反证 |

## 两个关键的语义修正

### 1. 代理客户端的符号（v2 修掉的反向 bug）

代理维度里混了两个不同的问题，v1 只用一个正权重，导致**"中文用户 + Shadowrocket"被推向美国**——
恰好把要排除的人群推向弹窗。v2 按群体拆分并给相反符号：

* **中文圈翻墙客户端**（Shadowrocket / Clash / Surge / Quantumult / V2Ray / Xray / sing-box）→ **−1.6**
  "人在墙内"的群体证据，这是本机最决定性的单个信号之一。
* **西式 VPN**（WireGuard / OpenVPN / NordVPN…）→ +0.2~+0.4 弱正向。
* **"有没有走隧道"** 是另一个问题，归 `proxy-route`（弱正向）。

### 2. 条件化证据：伪造特征存在时不采信代理归属

翻墙客户端说明"人在墙内"，但**当本机同时出现刻意覆盖时区/区域的特征时，这条证据就不再说明问题**
——那正是有人同时挂代理、又把时钟拨到美国的情形。所以：

```
spoofSignature = (时区指向美国 且 (区域是中文圈 或 有中文输入法))
              或 (时区指向中国 且 区域是美国)
```

`spoofSignature` 为真时，中文圈代理客户端这一项**不计分（降级为 informational）**。
没有这条规则时，标定会失败：见下面第 6 号画像。

## 阈值与标定

`THRESHOLD_LOGIT = 2.2`，由 `scripts/calibrate.mjs` 的 10 个画像标定：

| # | 画像 | 期望 | 说明 |
|---|---|---|---|
| 1 | 上海中文用户 + Shadowrocket（本机画像） | 非美国 | 强反证压过翻墙行为 |
| 2 | 上海中文用户，无代理 | 非美国 | |
| 3 | 美西英文用户（纯美式环境） | 美国 | 跨源全指向美国（`hard`） |
| 4 | 美东英文用户 + 商业 VPN | 美国 | 西式 VPN 不触发反证 |
| 5 | 中文系统 + 英文浏览器（只改了语言） | 非美国 | 单一正向信号不够 |
| 6 | 中文系统 + 伪造美国时区 + 英文浏览器 | 美国 | **条件化证据 + 伪造特征**起作用 |
| 7 | 在沪美国侨民（英文系统 + 中文输入法 + 上海时区） | 美国 | |
| 8 | 在美中国留学生（中文系统 + 美国时区 + 中文输入法） | 非美国 | 与 6 号只差浏览器语言与软件分布 |
| 9 | Linux/Docker 伪装成桌面 | 非美国 | |
| 10 | 极简环境（什么证据都没有） | 非美国 | 无证据不弹窗 |

当前最小裕度约 **0.5**（6 号画像，`+0.5` 超出阈值）。

**6 号与 8 号共享同一个 `spoofSignature`，只靠浏览器语言和软件分布区分**——这是模型当前已知的
最脆弱之处。改系数前先跑 `node scripts/calibrate.mjs`，看这两个画像的裕度是否还够。

## 记忆（历史）的模型兼容

`localStorage` 里的历史行带 `model` 字段。旧行（v1 权重和、或没有 `model` 字段的行）按 v1 口径重放：
`american === true && score >= 60` 才算命中。v2 行按 `american === true` 算。
见 `replayHistory()` / `rowIsAmerican()`（`src/client/score.js`）。

这样升级模型**不会**清掉你的警报状态，也不会让旧行按新尺度被重新解释。

## 调系数的工作流

```sh
node scripts/calibrate.mjs                # 画像表 + 裕度
node scripts/calibrate.mjs --verbose      # 每个画像的逐信号分解
node scripts/dryrun.mjs                   # 用本机真实数据跑一遍（zh-CN 浏览器）
node scripts/dryrun.mjs --lang en-US --zone America/Los_Angeles
node scripts/dryrun.mjs --ip              # 允许那一次公网 IP 查询
node scripts/test-all.mjs                 # 构建 + 两套功能测试 + 标定
```

改系数或阈值的顺序：先跑标定看画像是否仍全过、裕度是否够；再跑 `dryrun` 看本机画像；
最后跑 `test-all` 确认功能测试没坏。**不要为了让某个画像通过而改画像本身。**
